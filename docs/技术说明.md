## 3  手机端记录与自动估时

### Mode 1：行程预约

用户填写行程名称、出发日期和时间，并在地图上依次选择规划路线上的位置。界面自动显示预计结束日期和时间，不再要求用户手动填写结束时间。每次调整路线、日期或出发时间，都会重新计算。

程序对相邻经纬度使用 Haversine 公式计算距离，再累加整条路线的距离。固定速度为 4 km/h，预计行程分钟数向上取整；预计结束时刻等于出发时刻加上预计行程时间。跨午夜、跨年和闰日均保存完整的结束时刻。

```
预计分钟数 = ceil(路线距离 / 4000 × 60)
预计结束时刻 = 出发时刻 + 预计分钟数 × 60 秒
```

4 km/h 取自 Ordnance Survey《Map Reading》中用于一般步行估时的参考值。这里采用经纬度路线的距离估算；路线点应覆盖实际规划的转折。坡度、路况和停留会改变实际耗时，因此超时记录仍需人工联系核实。

| 保存字段 | 含义 |
| --- | --- |
| waypoints | 用户依次选择的规划路线位置 |
| expectedEndAtMs | 预计结束时刻，Unix 毫秒 |
| endDate / endTime | 供界面显示的结束日期和时间 |
| routeDistanceM | 路线累计距离，米 |
| estimatedDurationMinutes | 向上取整后的行程分钟数 |
| walkingSpeedKmh | 固定为 4 |
| estimationMethod | route_distance_fixed_speed_v1 |

### Mode 2 与 Mode 3

Mode 2 上传登山过程中的 GPS 位置和采样时间；地面站根据最近的有效采样判断是否超时，并在派飞时使用已经上传的历史定位序列。Mode 3 保存用户触发 SOS 时的求助位置和请求信息，供操作员核实及生成方形螺旋搜索路线。

自动估时见 M/services/eventBookingRecord.ts；预约界面见 M/pages/EventBookingPage.tsx；对应测试见 M/__tests__/eventBookingRecord.test.ts。

参考资料：Ordnance Survey, Map Reading, “Timing”, 印刷页 23。完整链接列于 docs/资料来源.txt。

## 4  地面站核实与任务派发

### 统一的核实流程

预约超时、定位更新超时和新 SOS 均进入待核实列表。操作员从平台查看用户本人及紧急联系人的信息，在实际联系后记录结果。确认用户安全时关闭该条提醒；无法确认安全时，继续联系可用的紧急联系人。完成这些记录后，操作员明确确认开展搜索，平台才创建搜索事件。

SOS 不再直接生成可派发事件。重复扫描不会重复创建提醒；重复确认不会重复创建事件。取消的 SOS 不能通过旧提醒继续确认。旧版未经核实且尚未执行的 SOS 事件需要重新完成联系核实，才能准备航线。

### 选定事件、查看航线、确认派发

操作员在任务列表选定事件后，地面站读取该事件关联的用户记录并生成航线。Mode 1 使用规划路线；Mode 2 使用按采样时间排序的历史 GPS 位置；Mode 3 以 SOS 位置为中心生成方形螺旋。操作员查看航线及设置，确认后发给无人机。派发期间若用户记录或操作状态发生变化，程序要求重新准备。

三个模式的事件初始级别一致。已有的等待时间处理规则对三个模式一致适用，SOS 不再因模式本身自动排在最高级别。选择和派发仍由操作员决定。

### 运行配置

| 环境变量 | 用途 |
| --- | --- |
| GS_FIREBASE_DATABASE_URL | 与手机端一致的数据库地址 |
| GS_FIREBASE_CREDENTIALS | 本机服务账号文件路径 |
| GS_T_LOCATION_UPDATE_SECONDS | Mode 2 更新超时阈值，正数，秒 |
| GS_T_WAIT_SECONDS | 列表等待时间阈值，正数，秒 |
| GS_EVENT_TIMEZONE | 旧预约记录的时区，模板为 Asia/Hong_Kong |
| GS_STATE_DIR | 任务派发日志的本地保存目录 |
| MQTT_BROKER / MQTT_PORT | 地面站与无人机共用的消息服务地址 |

配置模板为 G/runtime.env.example。填入实际值并导出为环境变量后，在 G 目录执行 python ground_station.py。模板中的两个阈值留空；测试中的 1 秒定位阈值仅用于检查时间边界。

核实流程见 G/rescue_event_manager.py；持久化与任务准备见 G/rescue_repository.py、G/active_event_queue.py 和 G/ground_station.py。

## 5  无人机端与外部飞行程序

### 接收任务和执行状态

地面站与无人机通过 Wi-Fi 网络传输任务和状态，软件使用 MQTT 消息。任务携带事件标识、执行标识、航点序列、飞行高度、悬停时间和返航设置。桥接程序检查任务内容后交给飞行执行程序，并将航点到达和任务阶段等状态返回地面站。

手机记录接收程序通过 HTTP 接口保存手机上传的数据。满足转发条件后，程序将记录发送到地面站；地面站保存并返回与记录标识和内容校验值相符的确认，无人机端再将该条传送标记为完成。录像程序将向下拍摄的视频保存在机载计算机中。

| 文件位置（U 内） | 作用 |
| --- | --- |
| catkin_ws/src/rescue_bridge/src/mqtt_bridge.py | 接收任务、交换执行状态 |
| catkin_ws/src/rescue_bridge/src/mission_commander.cpp | 执行航点及返航阶段 |
| drone_system/receiver/phone_sos_receiver.py | 接收、保存和转发手机记录 |
| drone_system/launcher/cam_recorder.py | 机载视频录制 |
| drone_system/launcher/drone_console.py | 机载程序状态与设置界面 |

## 6  MATLAB 三模式山地仿真

仿真使用西贡北潭涌附近地形。三种模式共享起飞位置和同一个山地区域目标，分别使用规划路线、派飞前的定位历史和目标周围的方形螺旋。所有模式均完成起飞、巡航、目标区域任务、返航和降落。

| 设置 | 取值 |
| --- | --- |
| 随机种子 | 20260926 |
| 起飞位置 | 22.402° N，114.322° E |
| 目标位置 | 22.40782761° N，114.35687745° E |
| 目标地面高程 | 约 177.44 m |
| 巡航离地高度 | 80 m，随地形升降 |
| 速度上限 | 水平 15 m/s；垂直 3 m/s |
| 航点悬停 | 5 s |
| Mode 3 螺旋 | 初始边长 30 m，每两段增加 30 m；首个距中心至少 200 m 的端点结束 |

### 运行入口

在 MATLAB 中将当前目录设为 simulation，然后选择所需入口：

```
run_all('paper')
run_all('simulate')
run_all('video')
```

paper 使用保存的轨迹生成论文图；simulate 重新计算全部模式并导出图件；video 生成动画，视频合成需要 ffmpeg。论文图写入 regenerated/paper；完整轨迹、统计及动画保存在 output。

| 模式 | 输入航点 | 到达目标 / s | 降落完成 / s |
| --- | --- | --- | --- |
| Mode 1 | 3 | 360.66 | 715.65 |
| Mode 2 | 15 | 409.08 | 764.07 |
| Mode 3 | 19 | 344.99 | 1008.53 |

高程文件为 Mapzen / Tilezen Skadi 的 N22E114.hgt，网格为 3601 × 3601、间隔 1 角秒。路线和 GPS 历史是按固定种子构造的仿真输入；表中时间从模拟起飞过程计时。完整参数、输入和执行轨迹分别见 scenario_and_settings.json、各模式航点 CSV 和 execution_trace.csv。

MATLAB 自带 30 项检查，独立 Python 核对包含 53 项检查，覆盖地形插值、80 m 离地高度、速度上限、航点顺序、返航降落和完整坐标框。
