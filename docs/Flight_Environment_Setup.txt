Flight Environment Setup

Platform: Ubuntu 20.04 and ROS Noetic, using catkin workspaces.

The manuscript prototype uses an Intel NUC 13 Pro, Pixhawk 4 Mini, Intel RealSense D435, a separate downward-facing recording camera and Wi-Fi. Manual control uses a RadioLink AT9S Pro transmitter and R12DSM receiver, with SBus to the flight controller. Pixhawk is the hardware controller; px4ctrl is an onboard software module in the external flight stack.

1. Download the pinned external flight project.

Run the following from this repository's root. The external/ directory is ignored by Git.

git clone https://github.com/Mikeahhh/FYP_alin1_SmartUAVRescueSystem_Drone.git external/drone-platform
git -C external/drone-platform checkout --detach b3ac1591b63d15270c9856e7b664da0cf9d3ea48

Fast-Drone-250 is in external/drone-platform/Fast-Drone-250.
For the original onboard directory layout, place it at /home/mike/Fast-Drone-250. Follow that pinned version's README for dependency installation, sensor parameters and flight-controller calibration.

2. Copy implementation/search_uav/catkin_ws and implementation/search_uav/drone_system from this archive to the onboard directories.

/home/mike/catkin_ws
/home/mike/drone_system

The original launch scripts use these paths. If the account name or installation location differs, update the corresponding configuration and launcher paths.

3. Build the workspaces in order.

source /opt/ros/noetic/setup.bash
cd /home/mike/Fast-Drone-250
catkin_make
source devel/setup.bash
cd /home/mike/catkin_ws
catkin_make
source devel/setup.bash

4. Configure the MQTT broker on the UAV computer, then start the flight programs and mission bridge.

The mission bridge currently connects without MQTT credentials. Use the local loopback listener for this component. The supplied rescue_bridge/config/mosquitto.lan-auth.example.conf configures one broker with a loopback listener and a separate authenticated LAN listener. Replace 192.0.2.10 with the UAV computer's actual LAN address and install the accompanying mosquitto.acl.example as /etc/mosquitto/rescue.acl. Use this combined configuration instead of loading it alongside mosquitto.conf, which defines the same loopback listener.

Create the broker password file interactively on the UAV computer:

sudo mosquitto_passwd -c /etc/mosquitto/rescue.passwd ground_station_role

Use -c only when creating a new password file; omit it when updating an existing file. Ensure the broker service can read its configuration, password and ACL files, then restart the service. The ground station connects to the UAV computer's LAN address on port 1883 with MQTT_USERNAME=ground_station_role and its corresponding MQTT_PASSWORD in the local runtime.env file. The ground station's localhost setting is only for a broker on that same computer; replace it for this onboard-broker layout.

Start the depth camera, MAVROS, VINS, planner and flight-control programs according to the external project instructions, then start the mission bridge:

roslaunch rescue_bridge rescue_bridge.launch mqtt_broker:=127.0.0.1

Default bridge parameters are flight_alt=5.0, arrival_threshold=1.0 and data_timeout=5.0. The MATLAB simulation's 80 m above-ground altitude does not override these settings.

5. Configure the phone-record receiver.

python3 /home/mike/drone_system/receiver/phone_sos_receiver.py --help

Copy /home/mike/drone_system/config/rescue_receiver.env.example to rescue_receiver.env in the same directory. For the onboard-broker layout, set UAV_RESCUE_MQTT_BROKER=127.0.0.1 and UAV_RESCUE_MQTT_PORT=1883, and leave the MQTT username and password empty. Fill the data directory and runtime token. If the receiver instead uses the authenticated LAN listener, create a receiver_role account with mosquitto_passwd (without -c) and supply its credentials as UAV_RESCUE_MQTT_USERNAME and UAV_RESCUE_MQTT_PASSWORD. The launcher exports this file before starting the receiver:

bash /home/mike/drone_system/bin/start_rescue_receiver.sh

The receiver's --help command only displays options. Directly launching the Python receiver requires exporting the same environment variables yourself. Before operation, check the flight-controller connection, positioning, camera indices and mission settings. Onboard recordings are managed by drone_system/launcher/cam_recorder.py and the console; inspect camera and log settings in drone_system/config/.

These steps describe onboard setup and startup. The original outdoor footage is available under docs/assets/outdoor/.
